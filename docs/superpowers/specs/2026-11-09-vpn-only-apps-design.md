# Приложения только через VPN

Дата: 2026-11-09. Часть Б из трёх улучшений маршрутизации. Опирается на модель правила из
`2026-11-09-rules-check-comments-design.md` (комментарий и выключение).

## 1. Цель

Человек выбирает программы, которые не должны выходить в сеть мимо туннеля. Пока идёт
сеанс FreeTurn, такая программа видит сеть только через адаптер туннеля. Если туннель ещё
не поднялся, переподключается или упал, у программы нет сети.

Маршрутизировать программу напрямую эта часть не умеет: таблица маршрутов Windows не знает
о процессах, а перенаправление средствами WFP требует подписанного драйвера.

Готово, когда:

- в настройках хранится список программ с комментарием и переключателем;
- от нажатия «Подключить» до «Отключить» включённая программа не открывает соединений мимо
  адаптера туннеля, в том числе к адресам из обхода;
- остальной трафик ведёт себя как раньше, в том числе без kill switch;
- после «Отключить» программы работают как обычно;
- отсутствующий файл программы не срывает подключение.

## 2. Принятые решения

| Вопрос | Решение |
| --- | --- |
| Когда действует блокировка | Только во время сеанса, от «Подключить» до «Отключить» |
| Конфликт с обходом | Программа строже: адрес из обхода для неё закрыт |
| Режим «через VPN только список» | Программа доступна только к адресам списка |
| Механизм | Фильтры WFP по `ALE_APP_ID` в существующей сессии брандмауэра |
| Когда действуют изменения | При следующем подключении |
| Падение службы | Динамическая сессия WFP исчезает, программы получают сеть до следующего подключения |

## 3. Настройки

```go
type AppRule struct {
	Path    string // абсолютный путь к .exe
	Comment string
	Off     bool
}

type Options struct {
	// ...
	Apps []AppRule
}
```

Проверку делает функция `split.CleanApps`. Окно вызывает её при сохранении, служба при
подключении:

- путь абсолютный с буквой диска (`C:\...`), без `..`, кончается на `.exe` без учёта
  регистра, не длиннее 1024 символов, без управляющих символов. Сетевые пути, каналы и
  пути устройств (`\\host\share`, `\\.\pipe`, `\\?\`) отклоняются: служба открывает файл
  под SYSTEM и отдала бы чужому серверу учётные данные машины;
- путь приводится к виду `filepath.Clean`, повторы ищутся без учёта регистра;
- не больше 50 программ;
- комментарий чистится так же, как у правил.

Существование файла при сохранении не проверяется: программу могут поставить позже.

Окно при неверном списке отказывает в сохранении. Служба окну не доверяет: неверный список
в запросе подключения срывает его с кодом `ErrBadProfile`.

## 4. Экран

На экране маршрутизации после списка правил раздел «Только через VPN»:

- кнопка «Добавить программу» открывает системный диалог выбора файла с фильтром `*.exe`
  (диалог Wails);
- карточка: переключатель, имя файла, полный путь приглушённым текстом, комментарий, кнопки
  «Комментарий» и «Удалить», устроенные как у правил;
- пустой список: короткое пояснение, что делает раздел;
- подсказка:
  - пока FreeTurn не подключён, программы работают как обычно;
  - в режиме «через VPN только список» программа доступна только к адресам из списка;
  - программы с версией в пути (`app-1.2.3\...`) после обновления нужно добавить заново;
  - дочерние процессы с другим exe не охватываются.

## 5. Брандмауэр

### 5.1. Параметры

```go
type Options struct {
	TunLUID   uint64
	DNS       []netip.Addr
	AllowLAN  bool
	Bypass    []netip.Prefix
	KillSwitch bool     // новый: blockAll и запрет DNS
	Apps      []string  // новый: пути программ только через VPN
}
```

Сейчас любая установка сессии это kill switch. После изменения `blockAll` и запрет DNS
ставятся только при `KillSwitch`. Вызовы движка, которые сейчас ставят блокировку,
передают `KillSwitch: true`.

### 5.2. Шаги и веса

| Шаг | Вес | Когда |
| --- | --- | --- |
| service (разрешение) | 15 | всегда |
| dns (разрешение / запрет) | 15 / 14 | `KillSwitch` и есть DNS |
| loopback | 13 | всегда |
| tun | 12 | есть `TunLUID` |
| dhcp, ndp | 12 | `KillSwitch` |
| lan | 12 | `AllowLAN` |
| apps (запрет) | 11 | есть `Apps` |
| bypass | 10 | `KillSwitch` и есть `Bypass` |
| blockAll | 0 | `KillSwitch` |

Обход опускается с 12 на 10, чтобы блок программ стоял выше него. Запрет DNS (14) остаётся
выше обхода, как раньше. Для трафика, не относящегося к программам из списка, порядок
разрешений и запретов не меняется: обход по-прежнему выше `blockAll`.

### 5.3. Фильтр программы

Для каждой программы `FwpmGetAppIdFromFileName0` даёт app id (функция уже используется в
`helpers.go` для службы). Фильтр запрета с одним условием `ALE_APP_ID == id` ставится на
уровнях `ALE_AUTH_CONNECT_V4/V6` и `ALE_AUTH_RECV_ACCEPT_V4/V6` с весом 11, без флагов,
как `blockAll`.

Разрешения адаптера туннеля, loopback и LAN стоят выше и пропускают программу туда. На
физический интерфейс программе остаётся только запрет.

Если app id получить нельзя (нет файла), программа пропускается: установка продолжается,
путь попадает в список пропущенных, который `Enable` и `Update` возвращают вызывающему.

## 6. Время жизни

Движок держит сессию WFP, если `Options.Blocks()` или есть хотя бы одна включённая
программа (`Options.AppsActive()`).

1. **Подготовка (шаг 1).** Если программы есть, движок ставит сессию с `Apps` и без
   `TunLUID`: программам закрыта вся сеть, кроме loopback. Это начало сеанса. `KillSwitch`
   в этой установке повторяет текущее состояние: если держится блокировка от прошлого
   подключения или от `ArmBlock`, она остаётся (`KillSwitch: true`), иначе kill switch до
   шага 5 не включается, чтобы сеть не пропала на время разрешения доменов. Обратная
   операция кладётся на стек отката до вызова, как у блокировки на шаге 5.
2. **Шаг 5.** `firewallOptions` добавляет `TunLUID`, `Apps` и `KillSwitch`. `Update` меняет
   сессию без разрыва, как сейчас. Если подключение началось под блокировкой, а kill switch
   в нём выключен, `blockAll` снимается отдельным `Update` только после успеха шага 5: сбой
   до этого места оставляет блокировку.
3. **Переподключение и смена сети.** Сессия остаётся, `fwRefresh` пересобирает её с теми же
   программами.
4. **Отключение или сбой без kill switch.** Сессия снимается. При сбое с kill switch
   сессия остаётся как есть, вместе с фильтрами программ: `blockAll` и так закрывает им
   сеть. После перезапуска службы `ArmBlock` ставит блокировку уже без программ.
5. **Падение службы.** Сессия WFP динамическая и исчезает. Следующий запуск службы программы
   не блокирует: сеанса нет.

Пропущенные программы дают предупреждение `WarnAppSkipped` в статусе и строку в журнале с
путём, по образцу `WarnRuleSkipped`.

## 7. Ошибки

- Нет файла программы: пропуск с предупреждением, подключение идёт.
- Сбой установки сессии WFP: сбой подключения с кодом `ErrAdapter`, как сбой блокировки
  сейчас. Без блока программ обещание «только через VPN» не выполнено, поэтому туннель не
  поднимается.

## 8. Тесты

- `firewall/options_test.go`: шаги и веса для сочетаний `KillSwitch`, `Apps`, `AllowLAN`,
  `Bypass`, `TunLUID`; без `KillSwitch` нет `blockAll`, dns, dhcp, ndp и bypass; блок
  программ ниже tun, loopback и lan и выше bypass.
- Проверка путей: относительный путь, не `.exe`, `..`, повтор в другом регистре, предел 50.
- `engine`: с поддельным брандмауэром. Программы без kill switch: установка на шаге 1 без
  LUID, `Update` с LUID на шаге 5, сессия держится при переподключении, снимается при
  отключении и при сбое. Пропущенная программа даёт предупреждение. Сбой установки срывает
  подключение.
- `firewall_admin_test.go`: блок для `curl.exe` без kill switch. Запрос мимо туннеля не
  проходит, после снятия сессии проходит. Пропуск несуществующего пути.
