# freeturn-windows: дизайн

Дата: 2026-10-31. Исходные данные: `docs/research-notes.md`.

## 1. Цель

freeturn-windows это полная версия клиента FreeTurn для Windows рядом с
`freeturn-lite-windows`. Человек ставит программу установщиком, импортирует ссылку
`freeturn://` и одной кнопкой поднимает туннель. Внешний WireGuard или Amnezia не нужны.

Первые получатели: автор и его знакомые, которым он сам даёт ссылку. Публичный релиз
возможен позже. Поэтому интерфейс рассчитан на человека без технических знаний, а
ошибки должны читаться без логов.

Критерии готовности:

- установщик ставит программу;
- программа импортирует ссылку и подключается одной кнопкой без внешних клиентов;
- трафик реально идёт через туннель;
- остановка снимает адаптер и маршруты;
- удаление не оставляет служб.

Все критерии проверяются на машине автора. Проверку на чистой Windows дают отзывы
знакомых после первой раздачи (раздел 12), отдельной чистой среды у проекта нет.

## 2. Принятые решения

| Вопрос | Решение |
| --- | --- |
| Архитектура | Своя Go-служба поверх `mobile` без форка ядра (схема C) |
| Интерфейс | Wails v3 + WebView2, язык русский, строки в одном файле |
| Конфиги | WireGuard и AmneziaWG |
| Kill switch | Есть, включён по умолчанию, отключается в настройках |
| Разделение трафика | Список IP, подсетей и доменов |
| Режим `mode: tcp` | Не поддерживается, для него остаётся лайт-версия |
| Подпись кода | Нет в первой версии, архитектура от неё не зависит |
| Установщик | Inno Setup, Windows 10 и 11, x64 |
| Обновления | Проверка через GitHub Releases, баннер со ссылкой |

## 3. Вне первой версии

- Разделение по приложениям. Нужен подписанный драйвер ядра. Задел: тип правила в
  модели (раздел 7).
- Готовый список «российские сайты напрямую».
- Шаблоны доменов `*.example.com` и перехват DNS.
- Постоянные правила брандмауэра, переживающие падение службы.
- Ручная настройка параметров ядра в интерфейсе.
- Подписки `subUrl`.
- Тихое автообновление.
- ARM64, Windows 7 и 8.

## 4. Компоненты

| Часть | Что делает | Права |
| --- | --- | --- |
| `FreeTurn.exe` | Окно, трей, профили, настройки | пользователь |
| `FreeTurnService.exe` | Служба `FreeTurnService`: ядро, WireGuard, сеть, брандмауэр | SYSTEM |
| `wintun.dll` 0.14.1 | Адаптер `FreeTurn`, подпись WireGuard LLC | внутри службы |

Пользователь запускает только `FreeTurn.exe`. Служба стартует вместе с Windows, у неё
нет окна и ярлыка. Пока туннель выключен, адаптера нет и сеть не меняется.

Закрытие окна сворачивает программу в трей, туннель продолжает работать. Пункт «Выход»
в трее отключает туннель и завершает программу. Плановое отключение не оставляет
блокировки брандмауэра.

Один Go-модуль:

```
cmd/freeturn/           окно и трей
cmd/freeturn-service/   служба, регистрация в SCM
internal/link/          разбор freeturn:// в профиль
internal/wgconf/        wg-quick в UAPI
internal/engine/        порядок запуска и откат
internal/protect/       обход туннеля для сокетов ядра
internal/netcfg/        адрес, маршруты, DNS, смена сети
internal/split/         правила обхода, разрешение доменов
internal/firewall/      kill switch
internal/ipc/           протокол и канал
internal/profile/       хранение профилей
frontend/               интерфейс
installer/              Inno Setup
```

`engine` работает через интерфейсы `Core`, `Tunnel`, `Network`, `Firewall`, поэтому
порядок шагов и откат тестируются без системных вызовов.

### Подключение ядра

Модуль ядра объявлен как `github.com/samosvalishe/free-turn-proxy`, но такого
репозитория на GitHub нет, код лежит в `hackdiaz-dev/free-turn-proxy`. Теги `v4.x` к
модулю без суффикса `/v4` не подходят. Рабочая схема проверена сборкой:

```
require github.com/samosvalishe/free-turn-proxy v0.0.0
replace github.com/samosvalishe/free-turn-proxy =>
    github.com/hackdiaz-dev/free-turn-proxy v0.0.0-20261028173317-562cfb4ba18b
```

Это коммит тега v4.1.1. Обновление ядра это смена псевдоверсии в `replace` и пересборка.
Версии зависимостей совпадают с `go.mod` ядра: `amneziawg-go/v3 v3.1.20260814`, Go 1.26.10.

Ядро в процессе службы используется только через `mobile`: `SetProtect`, `SetEventSink`,
`SetStateDir`, `Start`, `Stop`, `GetState`, `Reconnect`, `Wake`. `routes` в конфиге ядра
всегда `false`: маршруты до TURN здесь не нужны, обход делает `SetProtect`.

### Канал между окном и службой

`\\.\pipe\FreeTurnService`, сообщения JSON по строкам. Доступ: SYSTEM и администраторы
полный, вошедшие пользователи чтение и запись.

Команды окна: `Connect` (профиль и настройки), `Disconnect`, `GetStatus`, `GetLogs`.
События службы: `State`, `Stats`, `Log`, `Captcha`.

Туннель один на машину. Второй вошедший пользователь видит состояние и может отключить
туннель.

### Граница доверия

Служба работает как SYSTEM и получает данные от пользовательского процесса, поэтому:

- проверяет профиль сама, данным окна не доверяет;
- не выполняет `PreUp`, `PostUp`, `PreDown`, `PostDown`: они игнорируются разбором;
- не запускает внешних команд с данными из профиля;
- хранит данные в `%ProgramFiles%\FreeTurn\Data` с правами только для SYSTEM и
  администраторов, как WireGuard для Windows. В `ProgramData` обычный пользователь может
  заранее создать или переместить папку, а в `Program Files` писать не может. Логи окно
  получает через канал.

### Соседство с Amnezia

Имена службы, адаптера, канала и GUID адаптера свои. Обе программы можно ставить рядом.
Два VPN одновременно работать не смогут: перед подключением программа предупреждает,
если маршрут по умолчанию держит другой туннельный адаптер, например Amnezia или Mihomo.

Физический интерфейс выбирается только среди адаптеров, которые не являются виртуальными
или туннельными.

## 5. Подключение

Интернет человека не меняется, пока туннель не доказал, что работает.

1. Проверить профиль, выбрать свободный порт на `127.0.0.1`. Порт `9000` не занимать:
   на нём работает лайт-версия.
2. Определить физический интерфейс, установить хук `SetProtect`.
3. Собрать JSON ядра из профиля без секции `tunnel`, вызвать `mobile.Start`. Ждать
   состояния `connected`. Капча показывается окном сразу.
4. Создать адаптер, задать адрес и MTU, поднять устройство amneziawg-go с
   `conn.NewDefaultBind`. `endpoint` пира равен выбранному локальному порту. Ждать
   рукопожатия до 20 секунд.
5. Разрешить домены из исключений, чтобы блокировка не отрезала интернет на время
   DNS-запросов. Включить kill switch, если он выбран. Добавить маршруты исключений, затем
   основные маршруты и DNS.
6. Состояние «Подключено».

Сбой шагов 3 и 4 откатывает всё сделанное, сеть остаётся нетронутой. Ожидание на шаге 3
не ограничено, пока капча открыта. Без капчи таймаут 60 секунд.

Отключение идёт в обратном порядке: маршруты и DNS, kill switch, устройство и адаптер,
ядро.

### Состояния

| Состояние | Когда |
| --- | --- |
| Отключено | Туннеля нет |
| Подключение | Шаги 1–5 |
| Нужна капча | Ядро прислало страницу с `manual=true` |
| Подключено | Шаг 6 пройден |
| Переподключение | Потоков 0, маршруты на месте |
| Ошибка | Фатальный сбой при выключенном kill switch |
| Интернет заблокирован | Фатальный сбой при включённом kill switch |

### Обрыв связи

Переподключается ядро, маршруты остаются. Служба следит за тремя событиями:

- смена сети: обновить индекс в `protect`, перенести исключения, вызвать `mobile.Reconnect`;
- выход из сна: `mobile.Wake`;
- ядро сообщает `connected`, а рукопожатия нет дольше 3 минут: `mobile.Reconnect` и
  предупреждение в журнале.

### Падение службы

Windows перезапускает службу. `%ProgramData%\FreeTurn\state.json` хранит признак «туннель
нужен», настройку kill switch, время загрузки системы и список применённых маршрутов
исключений, без секретов. Маршруты исключений лежат на физическом адаптере и после падения
сами не исчезают, поэтому служба удаляет их при старте.

- Плановое отключение и нормальное завершение Windows сбрасывают признак.
- Если признак стоит, время загрузки совпадает и kill switch включён, служба сразу
  возвращает блокировку.
- Если признак стоит и время загрузки совпадает, окно отправляет профиль последнего
  подключения заново. Это работает и при выключенном kill switch.
- Если время загрузки другое (отключили питание), признак сбрасывается. Иначе человек
  остался бы без интернета после перезагрузки.
- Кнопка «Отключить» в состоянии «Интернет заблокирован» снимает блокировку и сбрасывает
  признак.

Правила брандмауэра живут в динамической сессии WFP и снимаются при смерти процесса.
Остаётся окно утечки на время перезапуска службы, около пары секунд. Это осознанный выбор:
постоянные правила при сломанной службе отрезают интернет до ручного ремонта.

«Запускать с Windows» включён по умолчанию, чтобы окно было на месте и могло
восстановить туннель.

## 6. Сеть

**Маршруты.** Строятся из `AllowedIPs` через `winipcfg`. `0.0.0.0/0` заменяется парой
`0.0.0.0/1` и `128.0.0.0/1`, `::/0` парой `::/1` и `8000::/1`, адаптер получает минимальную
метрику. Такая пара точнее любого маршрута `/0`, поэтому FreeTurn выигрывает у другого
адаптера с тем же маршрутом и метрикой, например TUN-адаптера Mihomo. Опыт показал, что
обычный `/0` ему не выигрывает. Маршруты исключений `/32` остаются ещё точнее.

**Обход туннеля.** `Protector` ставит на каждый сокет `IP_UNICAST_IF` и
`IPV6_UNICAST_IF` с индексом физического интерфейса. Значение для IPv4 передаётся в
сетевом порядке байт. Хук не знает семейство сокета, поэтому пробует оба варианта и
считает успехом любой. Если физического интерфейса нет, `Protect` возвращает `false`:
сокет не должен уйти в туннель.

Хук покрывает TURN (`turndial`, `netconn`) и DoH (`dnsdial`). Локальный UDP-сокет ядра
создаётся без хука (`session.go:504`), а трафик WireGuard идёт на `127.0.0.1`, поэтому
петли нет.

**IPv6.** Если в конфиге нет IPv6-маршрутов при полном туннеле IPv4, пара `::/1` и `8000::/1`
направляется на адаптер без IPv6-адреса и трафик отбрасывается.

**DNS.** Адреса строки `DNS` ставятся на адаптер. Без них остаётся системный DNS, а в
журнале появляется предупреждение.

**MTU.** Поле `mtu` ссылки, иначе `MTU` конфига, иначе 1280.

**Исключения.** IP и подсети получают маршрут через физический шлюз. Домен разрешается
при подключении и каждые 5 минут через DNS-серверы физического интерфейса по защищённому
сокету, адреса добавляются как `/32` и держатся до отключения. При смене сети маршруты
переносятся.

Ограничения доменов: работает только точное имя, `example.com` не включает
`www.example.com`. Сайты на CDN могут обходить туннель не полностью: браузер иногда
получает другие адреса, особенно со своим DoH.

**Kill switch.** Пакет `tunnel/firewall` из wireguard-windows (MIT) копируется в
`internal/firewall` с сохранением заголовков: его функции закрыты, а нам нужны
дополнительные разрешения. Разрешены сама служба (правило привязано к пути exe и SID, а не
ко всем процессам SYSTEM), loopback, адаптер `FreeTurn`, DHCP, NDP, локальная сеть и
исключения. Остальное блокируется. DNS разрешён только на адреса из
конфига. Доступ к локальной сети включён по умолчанию и отключается в настройках.

Разрешения обновляются транзакцией при смене адресов доменов и смене сети. До шага 5
блокировки нет: капча и запуск ядра не должны зависеть от туннеля.

## 7. Профили и правила

Импорт: кнопка «Вставить из буфера», поле ввода, клик по ссылке `freeturn://` (схема
регистрируется установщиком). Профиль добавляется только после подтверждения.

Разбор повторяет `FreeturnUri` лайт-версии: `base64url` без `#` и `?`, поля `v`,
`provider`, `peer`, `transport`, `mode`, `obf`, `key`, `timing`, `n`, `spc`, `cid`, `dns`,
`dnss`, `mcap`, `name`, `vk`, `wg`, `mtu`. Поля `listen`, `bond`, `kcp` игнорируются:
порт выбирает служба, а `bond` и `kcp` относятся к режиму TCP. Обязательны `v=1`,
`provider`, `peer`.

Поддерживаются провайдеры `vk` и `direct`.

Поля `vk` и `wg` ядро не описывает, их добавляет Android-клиент, и в ссылке их может не
быть. Поэтому профиль дополняется вручную:

| Чего нет | Что делает программа |
| --- | --- |
| `vk` при `provider=vk` | Просит ссылку на звонок. Её же можно заменить, когда она устареет |
| `wg` | Просит вставить конфиг или выбрать файл `.conf` |
| `cid` | Генерирует 16 случайных байт в hex и показывает ID для передачи владельцу сервера |
| `mode: tcp` | Отказ: такая ссылка предназначена для лайт-версии |

Других настроек ядра в интерфейсе нет.

WireGuard-конфиг: требуется ровно один пир. Разбор и перевод в UAPI копируются из
`internal/tunnel/wgconf` и `internal/tunnel/uapi.go` ядра (около 400 строк, Happy Bunny
License, уведомление сохраняется). Импортировать их нельзя: это `internal`.

Правила обхода общие для всех профилей:

```go
type Rule struct {
    Kind  RuleKind // ip, subnet, domain; позже app
    Value string
}
```

## 8. Интерфейс

Главный экран: кнопка «Подключить», состояние, выбор профиля, скорость, число живых
потоков, баннер новой версии.

Вкладки: Профили, Исключения, Настройки, Журнал.

Настройки: kill switch, доступ к локальной сети, запуск с Windows, подключение при
запуске.

Трей: значок по состоянию, «Подключить/Отключить», «Открыть», «Выход».

Капча: окно WebView2 с адресом от ядра и запасная кнопка «Открыть в браузере». Если
`OnCaptcha` пришёл с `manual=false`, окно не показывается, автоматическую проверку
проходит ядро.

## 9. Данные и секреты

| Что | Где | Защита |
| --- | --- | --- |
| Профили с ключами | `%LOCALAPPDATA%\FreeTurn\profiles.dat` | DPAPI под пользователя |
| Настройки, исключения | `%LOCALAPPDATA%\FreeTurn\settings.json` | без секретов |
| Признак туннеля | `%ProgramData%\FreeTurn\state.json` | без секретов |
| Состояние ядра | `%ProgramData%\FreeTurn\core\` | права SYSTEM и администраторов |
| Логи службы | `%ProgramData%\FreeTurn\logs\`, 3 файла по 1 МБ | секреты замаскированы |

Профиль попадает в службу на время подключения и хранится только в памяти.

Маскировка идёт по значениям: приватный ключ, PSK, ключ обфускации, Client ID и ссылка на
звонок заменяются в каждой строке до записи и отправки в окно. «Сохранить диагностику»
выгружает журнал в файл, который безопасно передать автору.

Настоящие ссылки и ключи не попадают в репозиторий, тесты и отчёты.

## 10. Установка, обновление, удаление

В `C:\Program Files\FreeTurn\` ставятся `FreeTurn.exe`, `FreeTurnService.exe`,
`wintun.dll`, папка `LICENSES`.

Установка:

1. Закрыть `FreeTurn.exe`, отключить туннель, остановить службу, если идёт обновление.
2. Скопировать файлы.
3. `FreeTurnService.exe install`: автозапуск, перезапуск при падении через 1, 5, 30 секунд.
4. Проверить WebView2. Если его нет, запустить встроенный загрузчик Microsoft.
5. Зарегистрировать `freeturn://`, создать ярлыки.

Обновление это установка поверх, профили и настройки сохраняются.

Проверка версии: раз в сутки запрос `releases/latest` репозитория, заданного при сборке.
Новая версия показывает баннер со ссылкой. Программа ничего не качает сама. При пустом
репозитории или недоступном GitHub проверка молчит. API и файлы релизов без токена доступны
только у публичного репозитория, поэтому закрытый код потребует отдельного публичного
репозитория для релизов.

Удаление:

1. Отключить туннель.
2. Остановить и удалить службу.
3. Убрать адаптер, автозапуск, схему `freeturn://`, `%ProgramData%\FreeTurn`.
4. Спросить про профили с ключами, по умолчанию удалить.
5. Вызвать `WintunDeleteDriver`. Он удаляет драйвер только если тот никем не занят, поэтому
   Amnezia не пострадает. Принудительно драйвер не удаляется.

В README входит инструкция для получателей: как пройти SmartScreen и что делать при
срабатывании антивируса.

## 11. Ошибки

| Ситуация | Сообщение |
| --- | --- |
| Служба не отвечает | Служба FreeTurn не запущена, переустановите программу |
| Другой VPN держит маршрут | Предупреждение: отключить его или продолжить |
| Реле работает, рукопожатия нет | Сервер WireGuard не ответил, проверьте профиль |
| Нет физической сети | Нет подключения к интернету |
| Ядро 60 секунд не подняло потоков | Сервер не отвечает. Проверьте адрес и что сервер версии 4.0.0 или новее |
| `INVALID_JOIN_LINK` | Ссылка на звонок недействительна, замените её |
| `CALL_FULL` | В звонке нет свободных мест |
| `ANON_BLOCKED` | Звонок запрещает анонимных участников |
| `FATAL_CAPTCHA_FAILED_NO_STREAMS` | Капча не пройдена |
| Адаптер не создался | Описание ошибки и кнопка «Сохранить диагностику» |

Отдельной ошибки для устаревшего сервера у ядра нет, поэтому эта причина только называется
в тексте про недоступный сервер. Остальные ошибки ядра показываются его текстом.

При старте служба удаляет адаптер и маршруты прошлой сессии, если они остались.

## 12. Проверка

### Опыты до написания интерфейса

Выполняются на машине автора с его согласия, потому что меняют маршруты. Код опытов
временный.

1. `IP_UNICAST_IF` работает при маршруте по умолчанию через адаптер: TCP/TLS-сокеты и
   двухстековые UDP-сокеты, которые Go создаёт для `ListenPacket(network, "")`.
2. Страница капчи открывается при включённом kill switch во время переподключения.

Если опыт 1 не прошёл: маленький патч ядра, чтобы хук видел адрес назначения, и точечные
маршруты `/32` до него. Если опыт 2 не прошёл: разрешить трафик WebView2 на время капчи.
Решение фиксируется правкой этой спецификации.

### Автотесты

На чистом Go, только сгенерированные ключи и выдуманные адреса:

- `link`: разбор ссылок, сценарии из `CoreConfigTest`, неполные ссылки;
- `wgconf`: конфиг в UAPI, AmneziaWG, `PreUp` игнорируется, больше одного пира отвергается;
- `split`: разбор правил;
- `engine`: порядок шагов и откат на каждом сбое, на заглушках;
- `ipc`: протокол;
- маскировка логов;
- `profile`: запись и чтение DPAPI.

С правами администратора, под отдельным тегом сборки: адаптер, маршруты, kill switch.

### Приёмка на машине автора

Только с его согласия:

1. Установка рядом с другим VPN-клиентом.
2. Импорт ссылки и подключение одной кнопкой без внешних клиентов.
3. Внешний IP равен адресу VPS.
4. Таблица маршрутов до подключения и после отключения совпадает, адаптера нет.
5. Kill switch: блокировка при обрыве, завершение службы, перезапуск.
6. Смена сети, сон и пробуждение.
7. Исключения: IP, подсеть, домен.
8. Удаление: `sc query FreeTurnService` не находит службу, адаптера нет, другой VPN-клиент работает.

### Обратная связь знакомых

Установка на чистой Windows отдельно не проверяется. На машине автора уже есть Go,
другие VPN-клиенты и драйвер Wintun, а в Windows 11 Home нет Sandbox и Hyper-V. Первая раздача
считается проверкой этого условия: получатели присылают результат установки и файл
диагностики. Пока отзывов нет, условие считается непроверенным.

## 13. Сборка и лицензии

Нужны Go 1.26.10, Node, Wails v3 CLI, Inno Setup. `build.ps1` собирает интерфейс и оба exe
с `CGO_ENABLED=0`, берёт `wintun.dll` по закреплённому хэшу SHA-256 и собирает установщик.
Скачанное проверяется по хэшу, загрузки поддерживают докачку.

Уведомления в `LICENSES`: ядро (Happy Bunny License), Wintun (лицензия на готовые бинарные
файлы), amneziawg-go, wireguard-windows, Wails. Код amnezia-client и turn-proxy-android под
GPLv3 не копируется, оттуда берутся только идеи.

Лицензия самого проекта выбирается перед публичным релизом.
