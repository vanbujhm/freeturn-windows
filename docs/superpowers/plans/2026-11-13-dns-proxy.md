# DNS-прокси: поддомены и журнал запросов. План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** На время сеанса служба становится DNS-сервером системы: правило `example.com` действует для всех поддоменов, маршрут ставится до ответа программе, а вкладка «Запросы» показывает, что спрашивали программы и куда это ушло.

**Architecture:** Новый пакет `internal/dnsproxy` слушает `127.0.0.53:53`. Он выбирает DNS-сервер той стороны, куда пойдёт трафик имени, пересылает запрос и ждёт до 1,5 с, пока движок поставит маршрут на адреса имени под правилом (`Sink.Apply`). Записи о запросах идут в кольцевой буфер службы. Система направляется в прокси правилом NRPT для `.` и DNS адаптера туннеля. Ключ NRPT записывается в файл состояния и снимается следующим запуском службы после падения.

**Tech Stack:** Go 1.26 (`golang.org/x/net/dns/dnsmessage`, `golang.org/x/sys/windows/registry`, `winipcfg`), Wails v3, TypeScript, vitest.

**Spec:** `docs/superpowers/specs/2026-11-09-dns-proxy-design.md`

## Global Constraints

- Доменное правило действует для имени и всех его поддоменов. Из нескольких совпадений выбирается самое длинное правило.
- Адрес прокси `127.0.0.53:53`, UDP и TCP, `SO_EXCLUSIVEADDRUSE`. Новых зависимостей в `go.mod` нет.
- Имя разрешается DNS-сервером той стороны, куда пойдёт его трафик (таблица в задаче 4). Без DNS в конфиге сторона туннеля берёт DNS физического интерфейса.
- Срок на запрос 3 с, делится между серверами поровну. `NXDOMAIN` окончателен. Все серверы молчат или ошибаются: `SERVFAIL`.
- Ответ программе уходит после возврата `Apply`, ожидание не дольше 1,5 с.
- Кеша в прокси нет.
- Предел 4096 динамических адресов за сеанс сверх разрешённых заранее, `WarnDNSLimit` один раз за сеанс.
- Буфер журнала запросов 2000 записей, адресов в записи не больше 8. Буфер не пишется на диск и не попадает в «Сохранить диагностику».
- Имена запросов не пишутся в журнал службы ни в какой строке.
- Если прокси не запустился, подключение идёт по прежней схеме с `WarnDNSProxy`.
- Заранее разрешаемые имена правил и `refreshDomains` остаются как есть.
- Ключ NRPT: `HKLM\SYSTEM\CurrentControlSet\Services\Dnscache\Parameters\DnsPolicyConfig\{FreeTurn-<guid>}`, `Name = "."` (REG_MULTI_SZ), `GenericDNSServers = "127.0.0.53"` (REG_SZ), `ConfigOptions = 8` и `Version = 2` (REG_DWORD).
- Тексты интерфейса только в `frontend/src/strings.ts`, на русском.
- Сборка с `CGO_ENABLED=0`. Все проверки: `pwsh -File test.ps1`. Админ-тесты: `pwsh -File test-admin.ps1 <файл>` в окне с правами администратора.
- Привязки Wails после изменения API окна: `cd frontend && npm run bindings` (в git не лежат).
- Файлы с путями Windows пишутся инструментом Write: heredoc в Bash портит обратные слэши. `internal/model/status.go`, `internal/netcfg/physical.go` и `frontend/src/style.css` хранятся с CRLF. В проекте нет Prettier, файлы не переформатируются.

## Review Focus

- Программа шлёт по UDP запрос, ответ на который больше 512 байт или с флагом TC: ответ уходит как есть, повтор по TCP проходит тем же выбором сервера. Тест в задаче 4.
- Сотни одновременных запросов при загрузке страницы: каждое имя под правилом ждёт только своё применение, сессия WFP пересобирается не на каждый ответ. Тест в задаче 6.
- Запрос во время отката сеанса или смены сети: ответ уходит (с `Late`), прокси не паникует, `Apply` после отмены сессии сразу возвращает ошибку. Тесты в задачах 4 и 6.
- Окно открыто после перезапуска службы: последний `Seq` службы меньше, чем помнит окно, и таблица начинается заново, а не застывает. Тест в задаче 9.
- Имя запроса в любом регистре и с точкой на конце (`WWW.Example.COM.`) совпадает с правилом `example.com`. Тест в задаче 2.

- [ ] **Step 1: Скрипт пробы**

```powershell
# Проба NRPT: применяет ли Dnscache правило для "." сразу после записи ключа и что для этого
# нужно. Запускать в PowerShell от администратора. На несколько секунд DNS машины уходит на
# 127.0.0.53, где никто не слушает. Ключ снимается в finally.
#Requires -RunAsAdministrator
$ErrorActionPreference = 'Stop'
$base = 'HKLM:\SYSTEM\CurrentControlSet\Services\Dnscache\Parameters\DnsPolicyConfig'
$key = Join-Path $base ('{FreeTurn-' + [guid]::NewGuid() + '}')
$names = [System.Collections.Queue]::new(@('example.org', 'example.net', 'iana.org', 'www.example.com', 'www.iana.org'))

function Probe([string]$label) {
    $name = $names.Dequeue()
    $rule = Get-DnsClientNrptPolicy | Where-Object { $_.Namespace -eq '.' -and $_.NameServers -contains '127.0.0.53' }
    $ok = $false
    $t = Measure-Command {
        $ok = $null -ne (Resolve-DnsName -Name $name -Type A -DnsOnly -NoHostsFile -QuickTimeout -ErrorAction SilentlyContinue)
    }
    '{0}: правило в действующей политике: {1}; {2} разрешился: {3} за {4:N1} с' -f $label, [bool]$rule, $name, $ok, $t.TotalSeconds
}

try {
    Probe 'до записи'
    New-Item -Path $key -Force | Out-Null
    New-ItemProperty -Path $key -Name Name -PropertyType MultiString -Value @('.') | Out-Null
    New-ItemProperty -Path $key -Name GenericDNSServers -PropertyType String -Value '127.0.0.53' | Out-Null
    New-ItemProperty -Path $key -Name ConfigOptions -PropertyType DWord -Value 8 | Out-Null
    New-ItemProperty -Path $key -Name Version -PropertyType DWord -Value 2 | Out-Null
    Probe 'сразу после записи'
    Start-Sleep -Seconds 2
    Probe 'через 2 с'
    Clear-DnsClientCache
    Probe 'после Clear-DnsClientCache'
}
finally {
    Remove-Item -Path $key -Recurse -Force -ErrorAction SilentlyContinue
    Clear-DnsClientCache
    Probe 'после снятия ключа'
}
```

Правило действует, если в его строке «правило в действующей политике: True», а имя не разрешилось.

```go
type Side string // "tunnel" | "direct"

const (
	SideTunnel Side = "tunnel"
	SideDirect Side = "direct"
	ApplyWait       = 1500 * time.Millisecond
	QueryTimeout    = 3 * time.Second
	MaxInflight     = 512 // одновременных запросов; сверх этого UDP-запрос отбрасывается, TCP ждёт
)

var Listen = netip.MustParseAddrPort("127.0.0.53:53")

type Sink interface {
	// Apply ставит разрешения и маршруты для адресов имени под правилом. Возвращается, когда
	// всё применено или ctx истёк.
	Apply(ctx context.Context, addrs []netip.Addr) error
}

type Upstreams struct {
	Direct           []netip.Addr // DNS физического интерфейса
	Tunnel           []netip.Addr // DNS конфига
	Direct4, Direct6 uint32       // индексы физического интерфейса для IP_UNICAST_IF
	Tunnel4, Tunnel6 uint32       // индексы адаптера туннеля
}

type Config struct {
	Listen     netip.AddrPort
	Domains    []string // split.Compiled.Domains сеанса
	TunnelOnly bool
	SplitOff   bool
	Upstreams  Upstreams
	Sink       Sink
	Log        *Log
	Logf       func(level, msg string) // уровни mobile.LevelWarn и т.п.
}

// Choice - куда идёт имя: правило, сторона трафика его адресов и сторона DNS-сервера.
type Choice struct {
	Rule     string
	Route    Side
	Upstream Side
}

func Choose(c Config, name string) Choice
func Start(c Config) (*Proxy, error)
func (p *Proxy) SetUpstreams(u Upstreams)
func (p *Proxy) Close() // ждёт выхода приёма; запросы в работе получают ответ или обрываются
```

`Choose` (таблица спецификации, раздел 4.2):

| Условие | Route | Upstream |
| --- | --- | --- |
| `SplitOff` | tunnel | tunnel |
| режим обхода, имя под правилом | direct | direct |
| режим обхода, имя не под правилом | tunnel | tunnel |
| «только список», имя под правилом | tunnel | tunnel |
| «только список», имя не под правилом | direct | direct |
| Upstream tunnel, а `Upstreams.Tunnel` пуст | без изменений | direct |

При `SplitOff` правило не ищется (`Rule` пуст).

- [ ] **Step 4: Реализация**

- Приём: `net.ListenConfig` с `Control`, ставящим `SO_EXCLUSIVEADDRUSE` (`windows.SetsockoptInt(h, windows.SOL_SOCKET, ^windows.SO_REUSEADDR, 1)`), для `udp4` и `tcp4` на `Config.Listen`. Сбой любого: закрыть открытое и вернуть ошибку.
- Разбор: `dnsmessage.Parser`, ровно один вопрос, иначе ответ `FORMERR` с ID запроса.
- Имя для `Choose` и журнала: `Question.Name.String()` без точки на конце.
- Пересылка: сырой запрос клиента уходит серверам выбранной стороны тем же транспортом, по очереди, каждому `QueryTimeout/len(servers)`. Сокет каждого запроса свой, `net.Dialer.Control` вызывает `bind(side, fd)`. Боевой `bind` ставит `IP_UNICAST_IF` по индексам стороны из текущих `Upstreams` через `protect.New()` + `SetInterface` + `Protect`; отказ привязки срывает запрос к этому серверу. Ответ сервера принимается, если ID совпал. `RCodeNameError` окончателен.
- Адреса: только из ответов A и AAAA разделов ответа, через `split`-фильтр непригодных (вынести `unroutable` в экспортируемую `split.Unroutable` без изменения поведения).
- `Sink.Apply` вызывается только при непустом `Rule`, ненулевом списке адресов и `RCodeSuccess`, с `context.WithTimeout(ApplyWait)`. Ошибка или истечение: `Late = true`, строка `Logf(mobile.LevelWarn, "маршрут для адреса из DNS не поставлен до ответа: " + причина)` без имени.
- Ответ сервера уходит клиенту байт в байт. UDP: одним датаграммом. TCP: с двухбайтной длиной, соединение обслуживает запросы по очереди, простой 10 с закрывает его.
- `MaxInflight` ограничивает одновременную обработку семафором.
- `Upstreams` хранятся под `sync.RWMutex`, каждый запрос берёт снимок.
